## 1. Open decisions

Each needs an answer from the owner. The recommendation is a starting point, not a decision.

### Blocking: the repository cannot go public until these are settled

1. **Group name.** Today it is "{{NAME}}". The domains openindus.org, .com and .net are registered by someone else, and "Read Indus" is a candidate.
   - *Recommendation:* pick a name whose GitHub organisation name and .org domain are both free. Then set `NAME` in `site/build.py`, set `REPO_URL`, and run the two build commands.
   - The name also goes into the copyright line of the licence files (decision 4) and into `CITATION.cff` (decision 8).
2. **Seal photographs, US status.** The website shows six crops:
   - Vats 1940 (Harappa): seal nos. 3 and 286;
   - Mackay 1938 (Mohenjo-daro): nos. 273, 289 and 461;
   - Marshall 1931: seal no. 91.

   The plate corpus adds 11 more crops from the same three reports. All are public domain in India. In the US, the 1938 and 1940 reports may carry restored copyright to the end of 2033 and 2035. US copyright for the 1931 report ends on 1 January 2027 in any case.
   - *Options:*
     - (a) get a short written opinion from a copyright lawyer;
     - (b) use only the 1931 plates, from 1 January 2027;
     - (c) replace the photographs with our own drawings.
   - *Recommendation:* (a). Until it is answered, (b) plus (c) is the safe fallback.
3. **Whole texts inside result files.** 18 result files list many complete Indus texts (section 3). The largest is `experiments/functional_reading/readings.csv`, which covers every text in Mahadevan 1977. Publishing them amounts to publishing the corpus, which the rest of the setup is careful not to do.
   - *Options:*
     - (a) ask the Roja Muthiah Research Library (Mahadevan 1977) and Wells and Fuls (ICIT) for permission;
     - (b) leave these files out and have each experiment rebuild them locally, as `data/` is.
   - *Recommendation:* ask; until there is an answer, (b).
   - The section 4 .gitignore does **not** yet exclude these files, because doing so breaks the rerun of those experiments for outside readers.
4. **Licences for our own work.** The proposal is MIT for code and CC BY 4.0 for writing, result data and our drawings, with the name and logo not licensed as a mark.
   - Once confirmed and the name is chosen, add `LICENSE` (MIT, copyright line "{{NAME}} contributors") and `LICENSE-docs` (CC BY 4.0). They are not written yet because they need the final name.
5. **The 11 Mahadevan sign drawings on the website.** They are embedded in `site/assets/glyphs.css`: M59, M60, M65, M66, M67, M99, M109, M176, M267, M342 and M391.
   - *Options:* ask the Roja Muthiah Research Library, or redraw the 11 as our own line drawings.
   - *Recommendation:* redraw. It is small and removes the question.
   - **Also on the landing page (added for design review):** the carved hero seal's row of 5 signs (M342, M99, M267, M176, M59), the faint field of 360 signs behind it, and the pressed sign strip used as a section divider (26 signs). All are Mahadevan 1977 drawings, copied by `site/build.py` into `site/assets/signs/` (364 files). **They must be redrawn as our own drawings, or cleared, before the site goes public.** M148 is never used.
6. **Contact routes.** The site's only public route is "open an issue". The code of conduct needs a **private** address for reports; today it shows a visible "NOT SET" notice.
   - *Recommendation:* a role address on the chosen domain, read by at least two people. Set `CONDUCT_CONTACT` in `site/build.py`.
7. **Frozen data split.** `scripts/reproduce.sh` needs `data/splits_v2.json`, the exact held-out split every v2 result uses, and it cannot be regenerated byte for byte. That file lists whole sign texts, so `/data/` stays out of the public repository. As things stand, outside readers cannot reproduce the split.
   - *Recommendation:* publish an ID-only version (text IDs plus the SHA-256 of the full file) and a loader that rebuilds the split from a freshly built corpus.
   - This touches `corpus/`, which belongs to the corpus agent. It needs its own task on the board.

## 2. Steps to publish, in order

1. Settle decisions 1 to 7.
2. Fix decisions 8 to 13 in the files named. For files owned by other agents, ask their owner or the board.
3. Set `NAME`, `REPO_URL`, `CONDUCT_CONTACT` and `BRANCH` in `site/build.py`, then run the two build commands at the top of this file.
4. Replace `README.md` with `README_PUBLIC_DRAFT.md` (decision 10), and add `LICENSE` and `LICENSE-docs` (decision 4).
5. Rename `.gitignore.proposed` to `.gitignore`.
6. In a **fresh copy** of the folder (so the private files never enter git history):
   1. Run `git init` and `git add .`.
   2. Check `git status --ignored` against section 3.
   3. Search the staged files once more for names, emails and `/Users/`.
7. Create the GitHub repository and push.
8. Turn on GitHub Pages for `site/`, or point the chosen domain at it.
9. Turn on private vulnerability reporting, and add the labels the issue forms use: `reading`, `bench`, `test proposal`, `error`, `data offer`.

## 4. The proposed .gitignore

The full file is `.gitignore.proposed`. In summary, it leaves out:

- **Environments and caches:** `.venv/`, `__pycache__/`, compiled and pickled files, logs, archives.
- **Private material:**
  - draft emails in `docs/outreach/`;
  - the live board database `board/board.db*`;
  - agent planning files `experiments/fable52_plan*` and `docs/fable_brief*.md`.
- **Third-party data:** `sources/`, all of `data/`, and every `experiments/*/raw|ext|data|work/` folder.
- **Nested repositories:** nested `.git/` folders.
- **Images:**
  - every image or PDF in `experiments/` except the 1931–1940 plate crops and the phase diagram;
  - the Chanhu-daro (1943) crops;
  - anything named `cisi_*`;
  - `experiments/iconography/`, `experiments/scene_text/` and `results/top120_signs.png`.
- **Superseded:** the older draft site in `docs/site/`.
