# Reproducibility report, v1.0 (2026-11-14)

**Result:**
- Every headline number in README that was re-run reproduces, except one.
- That one is the Gulf result's q across all tests (README #4, q=0.086). It depends on Python's hash seed. Re-runs give q = 0.020 to 0.086. The verdict does not change: the ranked claim already rests on the confirmatory q, which stays below 0.005 under every seed.
- One data file cannot be regenerated byte for byte: `data/splits_v2.json`. `corpus/build.py` breaks ties in a non-deterministic way, so a fresh build gives a different held-out set. The committed file is the one every v2 result used. Its hash is intact.
- 13 of 174 prereg hash lines do not match the current file. Four preregs had amendments appended after hashing and were never re-hashed. One prereg (`signlist_robustness.md`) changed with no amendment.

How it was run:
- Everything ran in scratch copies under `/tmp`, so no committed output was overwritten.
- Python 3.15.0 from `.venv`, pinned in `requirements.txt`.
- Each script was capped at 20 minutes. None hit the cap; the longest took 8 minutes (`decipherability/indus_run.py`).
- To repeat: `scripts/reproduce.sh`.

## Two causes of drift found

1. **Split version.** Wave-1/2 scripts call `dev_heldout()` with the default argument. When they ran (11:50 to 12:45 on 2026-11-14), the default was split v1. `splits_v2.json` was created at 14:08 and became the default. Re-running those scripts today silently uses v2 and gives different held-out numbers. Re-run with the default set back to v1 (in a scratch copy only), they reproduce. README already reports their top claims on v2 through `experiments/revalidation/`, and that reproduces exactly.
2. **Hash seed.** Many scripts iterate over Python sets, and the original runs did not fix `PYTHONHASHSEED`. Seeded permutation tests still give slightly different p-values from run to run. Running `ledger/v2_reruns.py` under seeds 0, 1 and 2 shows the size of the effect:

| Quantity (README) | Committed | Seed 0 | Seed 1 | Seed 2 |
|---|---|---|---|---|
| Gulf round seals, ledger `lr_gulf` p / q_all (README #4: q 0.086 across all) | 0.0005 / 0.086 | 0.00025 / 0.045 | 0.0005 / 0.086 | 0.0001 / 0.020 |
| Functional reading lexicon-permutation p (README #9: p=0.013) | 0.0133 | 0.0166 | 0.0066 | 0.0100 |
| Animal emblem held-out p (ledger D) | 0.093 | 0.063 | 0.033 | 0.050 |

The same mechanism makes `corpus/build.py:splits_v2` non-deterministic. A family's majority site is picked with `max(set(...))`, and ties are frequent. Two fresh builds under different seeds gave held-out hashes `1ddb83e0…` and `7b004dd3…`. The committed hash is `0174215d…`. About 220 of 571 held-out texts differ between builds. `scripts/reproduce.sh` therefore checks the committed file and does not rebuild it. It also fixes `PYTHONHASHSEED=0` so that future re-runs agree with each other.
