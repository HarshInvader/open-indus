# Research state (read this first every cycle)

The lead (main Claude session) runs the project in cycles: read this file, pick the top queued item(s), run them (usually as parallel Opus agents briefed with docs/AGENT_BRIEF.md), red-team anything positive, log the outcome here, update README if a ranked finding changes, post a short update to the owner. Fable is consulted for planning only, never to run experiments.

## Standing rules
- Goal: an actual reading (sign values / meanings / language) that survives held-out tests. Success test for sound values (2026-11-17, see Log): sound values count only if (a) they are supported by an anchor outside the texts (a name tied to an object, a bilingual, or independently fixed sign values) and (b) they correctly predict texts they were not fitted to, under a pre-registered test, and they survive an independent red team. Our bench alone can refute a key but cannot confirm one. Partial structure is a step, not the goal. Don't stop; when a route closes, open a different one.
- Held-out = `dev_heldout(version=2)` (family split, zero near-copy leakage). v1 leaked.
- Every positive claim gets an independent red-team reimplementation before it enters README.
- Keep a test ledger: every confirmatory test is pre-registered in `docs/prereg/` (hypothesis, prediction, test, threshold) BEFORE it is run on held-out.
- Max ~5 agents per cycle. Prefer cheap, high-information experiments.
